# Deep clone reactive state

Two small functions for getting a plain, independent snapshot of Vue reactive state, all the way down — unlike Vue's own `toRaw()`, which only unwraps the top-level Proxy and leaves anything nested still reactive. `deepToRaw` strips reactivity recursively; `cloneRaw` strips it and then deep-clones what's left.

## How it works

Vue's own `toRaw()` only unwraps the *top-level* Proxy — `toRaw(reactive({ a: { b: 1 } })).a` is still reactive, because `reactive()` wraps nested objects lazily, on access, and `toRaw` doesn't walk into them. `deepToRaw` recurses through refs (`isRef` → unwrap `.value`), reactive proxies (`isReactive`/`isProxy` → `toRaw` then recurse), arrays, `Map`s, `Set`s, and plain objects, so every level of nesting ends up genuinely reactivity-free — not just the top one, and not just the container: rebuilding a `Map` from its unwrapped entries and a `Set` from its unwrapped members means a `ref` or reactive object stored *inside* either one gets stripped too, not just the `Map`/`Set` itself.

Its `isPlainObject` check (`Object.prototype.toString.call(value) === '[object Object]'`) is deliberately one cheap string comparison, not a check that also tries to distinguish a plain object from an arbitrary class instance — both report `[object Object]` unless the class defines its own `Symbol.toStringTag`, so a class instance ends up walked into and rebuilt as a plain object the same as a genuine object literal would be, losing its prototype and methods. That's a trade-off made on purpose: the realistic shape of what passes through this — form state, API payloads — is plain objects, arrays, `Map`/`Set`, and primitives, not class instances, so the check stays fast and simple for the case that actually matters rather than paying for a prototype check on every call to guard a case that's rare here. One upside of doing it this way: because a class instance gets walked into rather than left alone, a `ref` sitting on one of its own properties still gets found and stripped as a byproduct of that same recursion — it's the class identity that's lost, not any reactive value hiding inside it.

`deepToRaw` already rebuilds a fresh container for everything it recurses into — a nested plain object, array, `Map`, or `Set` in the result is a new instance, not the one the reactive state holds, so mutating it doesn't touch the original. What it doesn't rebuild is whatever falls through untouched: a `Date`, a `RegExp`, or a function keeps the exact same reference it had in the live state, so mutating that specific value would still mutate what the original reactive state points at, since there was never a copy of it to begin with. `cloneRaw` finishes the job with `structuredClone` for genuine independence even in that remaining case — safe to hand to an API call, store as a "before" snapshot for a dirty-check, or mutate freely without any risk of it silently affecting the live form state. Running `deepToRaw` first isn't just cleanup, either: `structuredClone` can't handle a live Vue reactive Proxy at all — pass one in directly and it throws `DataCloneError: #<Object> could not be cloned` immediately, before it even looks at what's inside. `deepToRaw` has to run first so `structuredClone` only ever sees plain, already-unwrapped values.

`structuredClone` can't clone everything even once it gets plain values, though — functions, DOM nodes, and a handful of other types throw when passed to it. That's rarely a real constraint for form/API-payload data, which is usually just plain data, but it does mean `cloneRaw` isn't a universal deep-clone for arbitrary application state; a value containing a function or a non-cloneable object needs a different approach. A class instance doesn't throw, but by the time one reaches this step `deepToRaw` has already flattened it into a plain object, per the trade-off above — so `cloneRaw` on a class instance comes back a plain object too, never `instanceof` the original class.
